📊 DATA SCHEMA
─────────────────────────────────────────────────────────────────────────────

Each earnings record contains 20 fields:

Identifiers:
  - symbol              Stock ticker (e.g., "AAPL")
  - company_name        Full company name

Dates & Time:
  - earnings_date       Announcement date (YYYY-MM-DD)
  - earnings_time       Time of day (BMO, AMC, TAS)
  - fiscal_quarter      Fiscal quarter ending

Financial Metrics:
  - eps_forecast        Analyst EPS estimate
  - eps_actual          Reported EPS
  - eps_surprise        EPS surprise (actual - forecast)
  - eps_surprise_pct    EPS surprise percentage
  - revenue_forecast    Revenue estimate
  - revenue_actual      Reported revenue
  - market_cap          Market capitalization
  - num_estimates       Number of analyst estimates

Partition Columns:
  - snapshot_date       When data was captured
  - snapshot_year       Year partition
  - snapshot_month      Month partition
  - earnings_year       Earnings year
  - earnings_month      Earnings month

Metadata:
  - scraped_at          Scraping timestamp

🎯 DESIGN DECISIONS
─────────────────────────────────────────────────────────────────────────────

1. Modularity at Library Level
   Each component (scraper, pipeline, query API, orchestration) is
   independently usable without requiring the others.

2. Daily Snapshots Strategy
   Store complete state each day instead of incremental updates.
   Enables historical analysis of estimate changes.

3. Hybrid Scraping Approach
   Try API first (fast), fall back to Playwright (reliable).
   Best of both worlds for robustness.

4. DuckDB Query Layer
   SQL queries on Parquet files with predicate pushdown.
   No separate database needed.

5. Dagster Integration Patterns
   Two implementations: @dlt_assets (simple) and custom (control).
   Choose based on requirements.

6. Configuration Management
   Pydantic models with env vars and YAML file support.
   Follows dlt-ibapi patterns for consistency.
